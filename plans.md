Added 2026-11-26 (ninth pass): edge drawers and .forgewidget import/export.
- Drawers: Desktop → shape menu (Floating, or Drawer on the left/right/top/bottom edge), or
  `window.mode: drawer` + `window.edge` in a manifest. Closed: an 18×110 handle on the edge of
  the screen the widget was on. Hover 350 ms or click opens it with a short slide; it closes
  700 ms after the pointer leaves or when another app is clicked, unless pinned (📌 in its
  toolbar) or you are typing in it. Drag the handle to move it along the edge. An open drawer
  can be resized; its size is kept. Instance fields: mode, edge, pinned, drawer_at. Core:
  src-tauri/src/drawer.rs. Changing the shape rebuilds the widget's window.
- Packages: Export (Library card or Add-ons list) saves <Downloads>/<id>-<version>.forgewidget.
  Import: drop a file on the Hub, double-click it (file type registered in the installer), or
  type its path in Add-ons. The import card shows name, version, author, files, size, what it
  will be able to do, and for an update the installed version and NEW permissions. Install
  unpacks to add-ons/<id>; a replaced add-on is moved to add-ons/.replaced/, never deleted.
  Refused: absolute paths, `..`, backslashes, links, non-files, encrypted entries, other
  compression, files > 20 MB, > 100 MB unpacked (counted while unpacking), > 2000 files,
  bad checksums, no widget.yaml, invalid manifests, ids starting with forge., shipped commands.
  Zip handled in src-tauri/src/packages.rs on the deflate library already in the app.
- Tested: 33 Rust tests (zip round trip, unsafe and damaged packages, zip bomb, links, a real
  widget folder; packages read by Python's zipfile and unzip, and a Python-made zip read back;
  drawer geometry on every edge, clamping, second screen). Real app on the hidden display:
  four drawers' handles at the right places (checked with xwininfo) beside a floating widget.
  In the built-in browser with a stand-in backend: click opens, leaving closes, pin keeps open,
  unpin closes, dragging slides without opening; import refuses a bad package, shows an update
  with its new permission, installs; export; shape menu.
- NOT tested: the slide animation and hover in the real window (clicks and hover do not reach
  WebKitGTK here), file double-click (needs the installed .deb and a desktop), drag-and-drop of
  a file onto the Hub, export writing to a real Downloads folder from the UI, Windows/macOS.

Added 2026-11-26 (tenth pass): the widget catalog (Hub → Browse) and the registry template.
- registry-template/: a ready-made repository for community widgets (README, widgets/,
  tools/build_index.py, .github/workflows/catalog.yml). The check refuses what the app refuses
  on import (forge. ids, folder not named after the id, links, >20 MB files, >100 MB, >2000
  files, shipped commands, unknown permissions, network wildcards/paths, bad versions). On main
  it builds site/index.json + site/packages/*.forgewidget (+ icons) and publishes to GitHub
  Pages. NOT PUBLISHED: the GitHub repository does not exist yet; creating it is the owner's call.
- Core (src-tauri/src/registry.rs): reads the catalog (https, or http on localhost only; 5 MB
  cap; drops entries with forge. ids, bad checksums or disallowed addresses; resolves relative
  addresses), downloads a package (size and SHA-256 must match the index, 100 MB cap) into the
  app's downloads folder, then the normal import screen (inspect_package / install_package).
  DEFAULT_INDEX is empty until the public catalog exists: Browse says so and has a "Catalog
  address" box (saved as registry_url in settings.json).
- Hub → Browse: search, kind filter, "Updates only", cards with author, version, size,
  permission chips, Install / Update from vX / Installed (versions compared numerically).
  The install screen is shared with Add-ons → Import (PackageCard.svelte).
- Tested: build_index.py on three sample widgets (passes) and on bad ones (forge. id, link to
  /etc/passwd, shipped command, wildcard host: all refused). Rust: address rules, index
  checks, checksum/size, a real download from a local server and a tampered one, and the whole
  chain on the built catalog served locally (read index → download → verify → open package,
  all three). Browse page clicked through in the built-in browser with that catalog behind a
  stand-in backend: empty state, set address, list, update with new permission, install.
  33 JS + 38 Rust tests (+1 ignored).
- NOT tested: the GitHub Actions workflow (needs the repository), a real https catalog,
  clicking in the real app window, remote icons.
- Owner to decide: create the public repository (name and owner), then set DEFAULT_INDEX;
